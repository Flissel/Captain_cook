## Spec — required corrections

Three statements in the brief are contradicted by the code. Each was verified directly; each changes what "done" means.

**Correction 1 — The composition and the availability checks already exist.**
The brief describes them as work to be written. They are written.

- `agenten/agent_runtime/runtime_entrypoint.py` @ `34a6c13` is 372 lines (on `main`: 213). It defines `compose_gateway_backed_runtime_app(*, settings, client, hermes, codex, artifacts) -> FastAPI`, which threads all three ports into `AgentRuntimeService`, and `preflight_runtime() -> RuntimeBootstrap`, which returns a composed binding instead of raising.
- The "real availability checks" are `_validate_binding()` in `agenten/agent_runtime/production_bootstrap.py`. It verifies 8 methods across the 3 ports (`HermesPlannerPort.plan`, `.design_agent`; `CodexExecutionPort.start`, `.resume`, `.status`, `.cancel`, `.heartbeat`; `ArtifactPort.require`), checking each is present, callable, `async`, and binds the right arity. The error text names port and method: `"runtime adapter binding does not implement HermesPlannerPort.plan"`. Fail-closed is preserved via `raise ... from None`.
- **Consequence:** the deliverable is *landing and proving*, not authoring.

**Correction 2 — The env contract is NOT unchanged.**
`load_runtime_adapters_from_env()` (`production_bootstrap.py`) requires **two additional variables**, both mandatory:

- `CAPTAIN_RUNTIME_ADAPTER_MANIFEST` — path to a generated adapter manifest
- `CAPTAIN_RUNTIME_ADAPTER_MANIFEST_SHA256` — expected SHA-256 of that manifest's bytes

Missing either yields `"missing required runtime adapter settings: ..."`. There is also an **optional** `CAPTAIN_PROVIDER_PROXY_URL` (`str | None = None`, pattern-constrained to `^http://127\.0\.0\.1:[0-9]{1,5}/v1$`). The manifest is **not committed** — it is generated by `scripts/generate-runtime-adapter-manifest.py` and exported by `scripts/live-demo-services.ps1`.

- **Consequence:** the four variables in the brief are necessary but not sufficient. Any acceptance run that sets only those four fails at preflight. This is a design property of the digest-pinned adapter loader, not a defect.

**Correction 3 — The ledger is MariaDB, not SQLite.**
Verified along two independent paths:

1. `scripts/live-demo-services.ps1:107-108` sets `TEST_MARIADB_DSN = mariadb://captain_test:<secret>@127.0.0.1:$MARIADB_TEST_PORT/captain_test`, then `LEDGER_DSN = $TEST_MARIADB_DSN`. Default `MARIADB_TEST_PORT` is `33306`; the ledger runs in the Docker service `mariadb-test`.
2. `gateway/store.py` imports `pymysql.err` and `blockchain.mariadb_storage.MariaDBStorage`. There is no SQLite path into the Gateway ledger.

Two things in the tree look like the ledger and are not:

- `/data/provider.sqlite3` belongs to `agenten/provider_proxy` — a different subsystem, excluded from this plan.
- `agenten/delivery/ledger.py` (tables `delivery_todos`, `delivery_events`, SQLite `?` parameters) is a separate delivery ledger, not the Gateway ledger that `LEDGER_DSN` addresses.

The ledger table this plan proves against is `blocks` in `blockchain/mariadb_storage.py`:

```sql
CREATE TABLE IF NOT EXISTS blocks (
    `index`        BIGINT NOT NULL PRIMARY KEY,
    parent_index   BIGINT NULL,
    block_type     VARCHAR(128) NOT NULL,
    data           JSON NOT NULL,
    status         VARCHAR(64) NOT NULL,
    children       JSON NOT NULL,
    metadata       JSON NOT NULL,
    hash           CHAR(64) NOT NULL,
    previous_hash  CHAR(64) NOT NULL,
    created_at     TIMESTAMP(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
    CONSTRAINT fk_blocks_parent FOREIGN KEY (parent_index)
        REFERENCES blocks (`index`) ON DELETE CASCADE
) ENGINE=InnoDB
```

- **Consequence:** the acceptance proof must be a direct **MariaDB** query against `blocks`, not a SQLite query. **The proof rule itself is unchanged and binding:** the entry must be read independently out of the database, and an agent's or a tool's assertion that it worked does not count.

## Global Constraints

- **Fail-closed is non-negotiable.** No fallback adapters, no stubs, no "degrade to in-memory". A genuinely missing port must abort startup with an error that names the port.
- **Errors never leak content.** Existing style: name the role/index/port, never the payload. Preserve `raise ... from None` cause suppression where it already exists.
- **Runtime binds loopback only.** `host: Literal["127.0.0.1"]` in `RuntimeEntrypointSettings` — do not widen it.
- **Port allocation:** Runtime `8091` (`CAPTAIN_RUNTIME_PORT`, default `8091`), Gateway `8090`. Do not swap.
- **Out of scope, stays not-claimed:** automatic worker recovery; n8n; Minibook. Do not implement, do not "quickly fix", do not add to the acceptance path.
- **`provider_proxy` is out of scope.** The runtime never imports the `agenten.provider_proxy` package — it only accepts an optional URL. Do not port the 8 `provider_proxy` files.
- **Preserve main's 7 fix commits.** `main` (`5aa409c`) contains #24, #26, #27, #28, #29, #30, #31, which the source branch predates. A naive merge or cherry-pick touching `agenten/constitution/gatekeeper.py`, `agenten/constitution/validators.py`, or `agenten/ledger_bridge/recorder.py` will **revert** them. Those three files are **excluded from the port**.
- **Line endings:** adapter sources are verified against git-committed bytes with EOL normalization. Files feeding a digest must be pinned `eol=lf` in `.gitattributes`. On Windows, `git add --renormalize` does **not** rewrite already-checked-out working-tree bytes — a file must be deleted and re-checked-out.
- **Canonical test command:** `python -m pytest -q --no-cov -rs -m "not live" --ignore=tests/live`, after `python -m pip install -r requirements-dev.txt`. Do not hand-assemble a venv — the pinned set matters (an unpinned pytest 9.1.1 produced 10 phantom failures on 2026-08-17).
- **Git discipline:** branch-per-task, Ready-PR, **no deploy**. Never force-push. Never bypass hooks.
- **Test data must be marked and removed.** Every record the acceptance run writes carries an identifiable marker and is deleted afterwards, with the deletion proven by the same independent query method.

## Task 4: Make runtime startup failures diagnosable

**Files:**
- Modify: `scripts/live-demo-services.ps1` — the runtime start block (around line 502) and the failure throw (around line 518)
- Modify: `.gitignore`

**Interfaces:**
- Consumes: Task 3's committed script.
- Produces: a runtime start that, on failure, leaves a readable error naming its cause instead of only `Runtime did not become healthy.`

**Why this task exists:** the start uses `Start-Process ... -WindowStyle Hidden`, which discards the child's stderr. When the health probe then times out, the throw says nothing about the cause. Yesterday's session burned three rounds guessing at missing environment keys because of exactly this. Fixing it before the live run is cheaper than debugging blind during it.

- [ ] **Step 1: Redirect the runtime process output to files**

Replace the `Start-Process` invocation with one that captures both streams:

```powershell
$stdoutLog = Join-Path $root 'runtime-stdout.log'
$stderrLog = Join-Path $root 'runtime-stderr.log'
$process = Start-Process $python `
    -ArgumentList '-m','agenten.agent_runtime.runtime_entrypoint' `
    -WorkingDirectory $root -WindowStyle Hidden -PassThru `
    -RedirectStandardOutput $stdoutLog -RedirectStandardError $stderrLog
```

- [ ] **Step 2: Surface the captured error when the health probe gives up**

Replace `throw 'Runtime did not become healthy.'` with:

